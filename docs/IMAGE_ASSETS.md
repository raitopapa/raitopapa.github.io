# 樹木管理ナビ 写真素材ガイド

写真素材が届いたらすぐデザインへ反映できるよう、配置先と採用基準を先に固定します。

## 推奨する最初の素材

| 用途 | 枚数 | 推奨内容 | ファイル例 |
|---|---:|---|---|
| トップヒーロー | 1-3 | 公園樹、街路樹、樹冠、幹と葉。文字を重ねるため余白がある横長写真 | `assets/images/hero/hero-tree-canopy.webp` |
| 病害虫確認カード | 1 | 葉、幹肌、病斑の雰囲気が分かる写真。症状断定に見えないもの | `assets/images/tools/tool-diagnosis-leaf.webp` |
| 剪定カレンダーカード | 1 | 枝、剪定ばさみ、高枝切りばさみ、剪定前後の枝ぶり | `assets/images/tools/tool-pruning-branches.webp` |
| 健全度チェックカード | 1 | 街路樹、公園樹、根元、支柱、点検風景 | `assets/images/tools/tool-checklist-street-tree.webp` |
| 活用対象セクション | 3 | 自治体・公園管理、ホームオーナー、造園・緑化業者を想起できる写真 | `assets/images/use-cases/use-civic-street-trees.webp` |
| ブログ記事 | 任意 | 記事テーマ別の葉、枝、幹、根元、害虫、キノコ、台風後の点検など | `assets/images/blog/blog-deadwood-check.webp` |

## 採用基準

- 自前写真を第一候補にする。
- 人物の顔、車のナンバー、表札、住宅住所、店舗名、学校名などが写らないものを使う。
- 私有地や個人宅の庭木は、権利・許可が明確なものだけ使う。
- 危険木・病害虫の写真は「診断結果の保証」に見えないよう、説明文を慎重にする。
- 日本の街路樹・公園樹・庭木の文脈に合う写真を優先する。

## 素材ソースの優先順位

1. **自前撮影**  
   サイトの信頼性・独自性・自治体/造園業者向けの説得力が最も高い。トップヒーロー、活用対象、ツールカードの主要ビジュアルは原則これを使う。

2. **公的機関の公開素材・資料画像**  
   農林水産省、環境省、国土交通省、自治体、研究機関など。記事内の説明・出典付き資料として使う。原則として出典表記を付ける。

3. **Wikimedia Commons**  
   樹種、病害虫、用語解説などに有用。ただし画像ごとにライセンスが異なるため、CC BY / CC BY-SA / Public Domain を個別確認し、`assets/images/SOURCES.md` に記録する。

4. **Unsplash / Pexels / Pixabay**  
   商用利用しやすいが、日本の樹木管理文脈から外れた「雰囲気写真」になりやすい。背景や仮素材に限定し、専門的な症状例・診断例には使わない。

## 外部素材の利用ルール

- ダウンロード前にライセンスページを確認する。
- 素材ごとに `assets/images/SOURCES.md` へ出典、作者、URL、ライセンス、確認日を記録する。
- CC BY / CC BY-SA は、ページ内または `SOURCES.md` に作者名とライセンスを明記する。
- 「商用利用可」「クレジット不要」でも、ブランドロゴ・人物・私有地・作品性の強い建物が写る素材は避ける。
- 病害虫・危険木の素材は、誤診や安全保証に見えないキャプションにする。
- 生成AI画像は当面使わない。樹木診断・安全・自治体向け文脈では実写の信頼性を優先する。

## 自前撮影チェックリスト

### 必ず撮る

- 樹冠を見上げた横長写真。トップヒーロー候補。
- 街路樹・公園樹の引き写真。自治体・公園管理向け。
- 庭木の全景。ホームオーナー向け。
- 剪定ばさみ、枝、切り口、剪定前後の枝ぶり。剪定カレンダー向け。
- 葉の黄変、斑点、虫食い。病害虫確認向け。
- 幹、根元、樹皮、空洞、キノコ、支柱。健全度チェック向け。
- 現地調査らしい記録風景。調査票、メジャー、樹木番号、地図など。

### 撮影時の注意

- 横長を多めに撮る。ヒーローやカードは横長が使いやすい。
- 文字を重ねる写真は、左または中央に暗い余白がある構図を優先する。
- ピントは葉・幹・切り口など主題に合わせる。
- 露出は明るすぎないようにする。白飛びした葉は補正しづらい。
- 顔、ナンバー、表札、住所、学校名、会社名、店舗名は写さない。
- GPS EXIF は公開前に削除する。

## 受け入れフロー

1. 元画像を確認し、個人情報・権利・用途をチェックする。
2. 採用画像だけを用途別フォルダへ配置する。元画像の大量保管はしない。
3. WebPへ変換し、必要ならJPEG fallbackを作る。
4. 画像サイズを用途に合わせて縮小する。
5. `assets/images/SOURCES.md` に記録する。
6. `alt` 文またはCSS背景の代替説明を決める。
7. `assets/css/tokens.css` の画像フックを `url(...)` に差し替える。
8. ローカルで表示確認し、LCP/CLSに影響がないか確認する。

## 画像サイズ

| 用途 | 推奨サイズ | 形式 |
|---|---:|---|
| ヒーロー背景 | 2000 x 1200px 前後 | WebP, fallback JPEG |
| カードサムネイル | 900 x 600px 前後 | WebP |
| ブログメイン画像 | 1200 x 800px 前後 | WebP |

## ファイル命名

小文字英数字とハイフンだけを使います。

| 用途 | 命名例 |
|---|---|
| ヒーロー | `hero-tree-canopy-park.webp` |
| 病害虫 | `tool-diagnosis-yellow-leaves.webp` |
| 剪定 | `tool-pruning-shears-branch.webp` |
| 健全度 | `tool-checklist-root-flare.webp` |
| 活用対象 | `use-civic-street-trees.webp` |
| ブログ | `blog-leaf-yellowing-closeup.webp` |

## alt 文の方針

- 画像の内容を短く具体的に書く。
- 「美しい」「高品質」など主観的な言葉を避ける。
- 症状写真は断定しすぎない。例: `黄変した庭木の葉の近接写真`
- 背景装飾だけの画像はCSS背景にし、本文画像として扱わない。

## 実装時の差し込み先

`assets/css/tokens.css` に画像用フックを用意済みです。素材確定後に `none` を `url(...)` へ差し替えます。

```css
--image-hero-home: url('../images/hero/hero-tree-canopy.webp');
--image-tool-diagnosis: url('../images/tools/tool-diagnosis-leaf.webp');
--image-tool-pruning: url('../images/tools/tool-pruning-branches.webp');
--image-tool-checklist: url('../images/tools/tool-checklist-street-tree.webp');
```

この段階では、画像フックは未使用のため本番UIには影響しません。写真が揃ったら、トップヒーロー、ツールカード、活用対象セクションの順で段階的に反映します。
